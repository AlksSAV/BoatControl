## 2. Решение

**PlatformIO + pioarduino 55.x + фреймворк Arduino (core 3.x), плата `seeed_xiao_esp32c6`.**

### Почему

1. **Уже установлено и годно.** Платформа 55.03.312 с C6, RISC-V toolchain, cmake, ninja, esptool — всё на месте. Ноль установок, ноль риска «не соберётся из-за окружения».
2. **Плата есть в PIO официально** — не нужно писать board-файл; variant уже содержит корректный маппинг XIAO C6 (см. п. 3) и `ARDUINO_USB_CDC_ON_BOOT=1` → отладка через USB без внешнего UART-модуля.
3. **Официальная платформа 6.10.0 для C6 не годится** — ловушка: при `platform = espressif32` без явного pinning на pioarduino сборка под C6 упадёт. Поэтому в `platformio.ini` версия платформы фиксируется явно.
4. **Arduino-core 3.x закрывает все требуемые периферии**: ADC1, LEDC (или RMT), GPIO, USB-CDC, SWDT. Wi-Fi/BLE и сторонние библиотеки не нужны — используемый слой тонкий.
5. **ESP-IDF standalone отвергнут**: тулчейн не настроен, а возня с `sdkconfig` и ручной сборкой ради задачи с пятью перифериями не окупается. При необходимости позже переключаемся на `framework = espidf` **в той же PIO** — каркас (папки, `config.h`, разделение логики и HAL-обёрток) это позволяет без переписывания логики состояний.
6. **Rust/esp-hal отвергнут**: нет установленной RISC-V-цепочки для ESP, а выигрыш (строгая типобезопасность) не оправдывает стоимость входа для проекта такого размера.

### Что принимаем как цену решения

- Arduino-core 3.x быстро меняется; API LEDC/ADC в 3.x отличается от 2.x. Лечится **жёсткой фиксацией версии платформы** в `platformio.ini` (не `@ latest`).
- HAL-вызовы прячем в тонкий слой `src/hal.*`, чтобы переход на ESP-IDF (если понадобится) не трогал логику из SPEC.

## 3. Подтверждённый маппинг пинов (из установленного варианта платы)

`~/.platformio/packages/framework-arduinoespressif32/variants/XIAO_ESP32C6/pins_arduino.h`:

```
D0=0   D1=1   D2=2   D3=21  D4=22  D5=23
D6=16  D7=17  D8=19  D9=20  D10=18
A0=0   A1=1   A2=2
LED_BUILTIN=15
TX=16  RX=17        SDA=22 SCL=23
SS=21  MOSI=18 MISO=20 SCK=19
WIFI_ENABLE=3       WIFI_ANT_CONFIG=14
```

Это **подтверждает** раскладку из [SPEC.md](SPEC.md) п. 3 и **добавляет** три важных факта:

| Факт | Последствие для проекта |
|---|---|
| `A0=0, A1=1, A2=2` | Аналог — ровно три выведенных входа. Под стик занято два (D0/D1), резерв один: D2. |
| `TX=16, RX=17` = D6/D7 | Наши LED на D6/D7 **забирают UART0**. Отладка идёт на встроенном USB-CDC (`ARDUINO_USB_CDC_ON_BOOT=1`) — это нормально, но `Serial` в коде = USB, а не D6/D7. |
| `SDA=22, SCL=23` = D4/D5 | Наши PWM на D4/D5 **забирают I2C**. I2C не используем (нет датчиков/GPS) — ок. Если когда-нибудь понадобится, PWM придётся переносить, а свободных пинов с доступом к LEDC на XIAO C6 немного. |

`WIFI_ENABLE=3`, `WIFI_ANT_CONFIG=14` подтверждают: GPIO3/GPIO14 не трогаем (иначе потеряем выбор антенны).

## 4. Команды

```bash
cd firmware
pio run                     # сборка
pio run -t upload           # прошивка (нужен свободный COM-порт XIAO)
pio device monitor          # лог по USB-CDC, 115200
pio run -t clean            # полная пересборка
pio pkg update -g -p espressif32   # обновление платформы (осторожно: API может измениться)
```

Если XIAO не определяется при `upload` — удерживать кнопку **BOOT** при подключении USB (download mode), затем повторить `pio run -t upload`.

## 5. Что обязательно проверить на первой сборке (до написания логики)

1. **Собирается ли `blink` для `seeed_xiao_esp32c6`** — подтверждает годность тулчейна.
2. **`Serial` = USB-CDC**: лог виден в `pio device monitor` без внешнего UART-адаптера.
3. **Число доступных LEDC-каналов** на C6 (заявлено «до 6»). Нам нужно ровно 2. Если каналы/таймеры конфликтуют — переходим на RMT.
4. **Джиттер импульса**: выводим 1500 мкс и измеряем (анализатор/осциллограф) разброс при загрузке CPU. Критерий: не хуже ±5 мкс. Хуже — RMT вместо LEDC.
5. **АЦП с полным аттенюатором**: реальный full-scale и где «4095» при 3.3 В на бегунке. Подтверждает `THR_SPAN_ADC` / `X_SPAN_ADC` / `ADC_VALID_MAX`.
6. **Сброс по SWDT** происходит и старт идёт с BOOT (SPEC п. 6).

## 6. Структура репозитория

```
BoatControl/
├── README.md              обзор проекта, как собрать и прошить
├── docs/
│   ├── SPEC.md            логика, карты, состояния, пороги, fail-safe
│   ├── HARDWARE.md        распиновка, схема, питание, BOM
│   └── PLATFORM.md        этот файл
├── firmware/              PlatformIO-проект
│   ├── platformio.ini     плата, фиксация версии платформы, флаги
│   ├── include/
│   │   └── config.h       ВСЕ параметры из SPEC п. 7 (единый источник)
│   ├── src/
│   │   ├── main.cpp       цикл 50 Гц, машина состояний
│   │   ├── hal.h/.cpp     тонкий слой: ADC / PWM / GPIO / LED / SWDT
│   │   └── ...            по мере реализации (throttle, steering, cruise, failsafe)
│   └── test/              host-тесты чистой логики (карты, состояния) — позже
├── hardware/              монтаж: описание + фото/схема, при необходимости KiCad
└── tools/                 Python: разбор логов калибровки, таблицы raw→pulse
```

Правило: **числа живут только в `config.h`.** В `src/*.cpp` не появляется ни один магический литерал, кроме констант формата RC-сигнала (1000/1500/2000) — и они тоже объявлены в `config.h`.
