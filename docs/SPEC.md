# SPEC

Плата: Seeed Studio XIAO ESP32-C6. Версия 0.2. Пороги подтверняются на стенде.

## 1. Состав

- ESC (мотор) по PWM 50 Гц, 1000–2000 мкс, реверс есть.
- Серва руля PWM 50 Гц, 1000–2000 мкс, без обратной связи и концевиков.
- Джойстик: JH-D400X-R4 (4 оси, 10 кОм, самовозврат X/Y, герметичный), используем X и Y.
- Кнопка круиза: только вкл/выкл.
- Индикация: светодиоды + активный зуммер (подтверждение круиза).
- Один пост управления. Внешней связи для УПРАВЛЕНИЯ нет; сервисный Wi-Fi
  (п.11) — только настройка и диагностика, органы управления не заменяет.

## 2. Пины

| Функция | Pad | GPIO |
|---|---|---|
| Стик X (руль), ADC | D0 | 0 |
| Стик Y (газ), ADC | D1 | 1 |
| Кнопка круиза | D3 | 21 |
| PWM → ESC | D4 | 22 |
| PWM → серва | D5 | 23 |
| LED готовность | D6 | 16 |
| LED круиз | D7 | 17 |
| Зуммер (активный) | D8 | 19 |
| Бортовой LED | — | 15 (active-low) |

Не трогать: GPIO3/14 (антенна платы), GPIO12/13 (USB), GPIO6–11 (SPI flash).
Аналог выведен только на GPIO0/1/2 (D0/D1/D2), ADC1.

## 3. Карты

Газ (ось Y), нейтраль 1500 = стоп:

- стик от себя → 1500 → 1000 = вперёд 0–100 %
- стик на себя → 1500 → 2000 = назад 0–100 %
- мёртвая зона с обеих сторон от 1500
- смена знака требует прохода через нейтраль + пауза
- набор газа ограничен по скорости, сброс быстрее
- полярность оси подтверждается на стенде (инверсия — константа)

Руль (ось X): влево 1000, центр 1500, вправо 2000, мёртвая зона у центра.
Программные упоры STB_PULSE_MIN/MAX ставятся чуть внутри механических.
Ход сервы ограничен по скорости: от упора до упора (STB_PULSE_MIN→STB_PULSE_MAX)
не быстрее `STB_SLEW_FULL_MS` (по умолчанию 2000 мс), линейно. Исключений нет —
в нейтраль после BOOT/CALIBRATE/CAL_MANUAL/FAULT серва тоже возвращается в этом
же темпе. Резкий перевод стика даёт плавный поворот руля.

## 4. Состояния

BOOT → CALIBRATE → READY → DRIVE ⇄ CRUISE, любой сбой → FAULT (сброс только перезапитанием).
Ручная калибровка хода (п. 5.5) — состояние CAL_MANUAL между BOOT и READY.

| Состояние | Газ | Руль | LED готовность | LED круиз |
|---|---|---|---|---|
| BOOT / CALIBRATE | 1500 | 1500 | выкл / медл. мигание | выкл |
| CAL_MANUAL | 1500 | 1500 | быстрое мигание + писки | выкл |
| READY | 1500 | 1500 | вкл | выкл |
| DRIVE | по стике | по стике | вкл | выкл |
| CRUISE | уставка жестом | по стике | вкл | вкл |
| FAULT | 1500 | 1500 | быстро мигает | выкл |

Значения в таблице — целевые. Фактический импульс сервы доходит до цели с
ограничением скорости хода (п. 3); газ подчиняется своему rate limit (п. 3, п. 6).

## 5. Арминг и тарировка

1. t=0: выходы 1500/1500, круиз выключен.
2. Пауза 1 с (требование: ESC готов через 1 с после включения).
3. Авто-тарировка нуля обеих осей (стик в покое), проверка допуска смещения, разброса и валидности АЦП.
4. Допуск не пройден → FAULT, индикация отличается от прочих ошибок:
   бортовой LED мигает **в противофазе** LED готовности (при прочих FAULT они синфазны).

Круиз после перезагрузки всегда выключен.

### 5.5. Ручная калибровка хода (min/max) и хранение в flash

Проблема: полный ход потенциометра у конкретного экземпляра стика отличается от
константы `THR_SPAN_ADC`, из-за чего порог жеста круиза «до упора» может не
достигаться. Решение — одноразовая процедура, результат в NVS.

Вход: удерживать кнопку круиза с подачи питания ≥ 0,5 с (порог достигается до
конца паузы арминга). Признаки входа: короткий писк, быстрое мигание обоих LED,
выходы 1500/1500. В BOOT/CALIBRATE/CAL_MANUAL кнопка не анализируется на
залипание — иначе 15-секундное окно ложно уводило бы в FAULT (п. 7).

Окно 15 с: оператор медленно переводит стик во все крайние положения обеих осей.
Каждый такт трекинг min/max; подтверждающий писк ~80 мс раз в 1 с («калибровка идёт»).
Крайние значения АЦП (~0 и ~4095) в этом режиме нормальны и отказом не считаются.

По истечении окна, для каждой оси: полуход = (max−min)/2, центр = (max+min)/2.
Провал → FAULT (бортовой LED в противофазе): полуход < `CAL_MIN_SPAN_ADC`
(стик не двигали) или > `CAL_MAX_SPAN_ADC`, либо запись/чтение NVS не подтвердилось.
Успех → полуходы пишутся в NVS (magic + версия + FNV-1a CRC + обратное чтение),
короткий писк, READY.

Ноль по-прежнему тарируется автоматически каждый старт (п. 5) — он дрейфует
от температуры; в NVS хранится только ход. Если записи NVS нет, карты и жест
работают по константам config.h (режим до v1.0).

Сброс калибровки: `cal_erase()` (для стенда) — вернёт работу по константам.

## 6. Круиз

- Включение коротким нажатием: только в DRIVE, только вперёд, газ выше порога.
  Короткий писк (~120 мс).
- Фиксируется **фактически выдаваемое** значение, не позиция стика.
- В активном круизе ось Y задаёт уставку жестом «до упора, затем в центр»:
  - стик от себя до упора → возврат в центр: +10 % хода (импульс −50 мкс);
  - стик на себя до упора → возврат в центр: −10 % (импульс +50 мкс);
  - «до упора» — отклонение ≥ 95 % хода, подтверждённое 3 такта подряд;
  - шаг применяется один раз и только после возврата стика в мёртвую зону;
  - верхняя граница — 100 % (1000 мкс), нижняя — стоп (1500 мкс);
  - уставка меняется с rate limit п. 3, без ступеньки;
  - шаг вверх — короткий писк (~100 мс), шаг вниз — средний (~250 мс);
    на верхней (100 %) и нижней (стоп) границах писк не звучит.
- Руль работает всё время.
- Достигнув стопа, круиз **не** выключается: газ 1500, LED круиза горит,
  выход — только кнопкой.
- Первый жест после включения круиза возможен только после прохода стика через центр.
- Выключение коротким нажатием → плавный возврат к позиции стика с соблюдением п. 3.
  Длинный писк (~500 мс).
- Длинное нажатие (2 с) → принудительный сброс круиза + длинный писк.
- Обрыв оси Y в круизе не роняет газ: жест игнорируется, уставка держится.
- Недостоверность зафиксированного значения (вне 1000…1500) → 1500 + FAULT.

## 7. Fail-safe

| Отказ | Действие |
|---|---|
| Обрыв/КЗ оси в READY/DRIVE | 1500/1500, FAULT |
| Обрыв оси Y в CRUISE | круиз держит |
| Недостоверный круиз | 1500, сброс, FAULT |
| Шум АЦП выше порога | 1500, повторная тарировка, иначе FAULT |
| Залипание кнопки | сброс круиза, FAULT |
| Просрочка такта (watchdog) | сброс платы → BOOT |

Выходы никогда не в Hi-Z. При инициализации сразу 1500 на обеих линиях.
Физический рубильник в силовой цепи обязателен, электроника его не заменяет.

## 8. Параметры (все — в `config.h`)

Период цикла 20 мс, oversampling АЦП, пауза арминга 1000 мс, нейтраль 1500, ход 500,
мёртвые зоны газа и руля, полные ходы осей, инверсии осей, rate up/down, пауза смены знака,
порог включения круиза, шаг и порог упора жеста, подтверждение упора, время возврата из круиза,
debounce/long/stuck кнопки, допуски тарировки (смещение, разброс), границы валидности АЦП, порог шума,
окно и порог ручной калибровки, минимальный/максимальный полуход, версия формата NVS,
программные упоры руля, частоты мигания LED, таймаут watchdog,
длительность писка зуммера: включение/выключение круиза, шаг уставки вверх/вниз.

## 9. Стенд (винт снят)

1. Полярность осей.
2. Фактическая нейтральная зона ESC → подогнать свою.
3. Смена направления: с паузой и без.
4. Подбор rate limit по току.
5. Смещение нуля на холодную и прогретую.
6. Шум АЦП при работающем моторе.
7. Программные упоры руля против механических.
8. Кнопка: short/long/debounce/залипание.
9. Круиз: включение, удержание, возврат, попытка реверса, длинное нажатие.
   Жест уставки: шаг вверх/вниз, доведение до стопа, отказ при неполном возврате в центр,
   ложные срабатывания на волне.
   Зуммер: писк при вкл/выкл круиза, разные писки шага вверх/вниз,
   молчание на границах (100 % и стоп).
10. Выдернуть/замкнуть ось Y в DRIVE и в CRUISE.
11. Сброс по watchdog.
12. Ручная калибровка (п. 5.5): вход удержанием кнопки, полный перевод стика во
    все крайние положения, проверка полухода, сохранение в NVS, повторный старт
    с использованием сохранённого хода; провалы: стик не двигали, кнопка отпущена
    слишком рано, обрыв оси в окне; после калибровки — жест «до упора» достигается
    на реальном стике.

## 10. Не хватает данных

Модели ESC, сервы, джойстика, батареи; длина проводов стика; ток BEC; уровень логики 3.3 В или 5 В.
Всё это уходит в `config.h` и схему, на логику не влияет.

## 11. Сервисный веб-интерфейс (SoftAP)

Назначение — настройка порогов и диагностика на стенде без перепрошивки.
Управлять мотором и сервой из веба **нельзя**: веб не имеет доступа к выходам,
он читает телеметрию и пишет параметры.

### 11.1. Окно доступности

- SoftAP поднимается в `setup()` (после `hal_init()`, чтобы арминг не задерживался
  инициализацией радио). SSID/пароль — константы `WEB_AP_SSID`/`WEB_AP_PASS`.
- Если за `WEB_AP_TIMEOUT_MS` (60 с) к точке ни одна станция не ассоциировалась —
  радио гаснет полностью (`WIFI_OFF`) и не поднимается до следующей перезапитки.
- Если клиент подключился и затем пропал дольше `WEB_AP_IDLE_CLOSE_MS` (5 мин) —
  окно закрывается так же.
- Переход в DRIVE, CRUISE или FAULT закрывает окно немедленно: веб не переживает
  начало движения. Возврата окна в том же сеансе нет — только перезапитание.
- `WEB_ENABLE=0` в `config.h` полностью исключает радио из сборки.

### 11.2. Что доступно

- **Телеметрия** (`GET /api/status`, опрос браузером каждые `WEB_POLL_MS`):
  состояние машины, фактические импульсы ESC/сервы, сырые и нормализованные
  значения осей, тарированные центры и полуходы, уставка круиза, текущие
  параметры и их границы.
- **Параметры** (`POST /api/params`): пороговые значения п.8, ставшие runtime
  (см. 11.3). Каждое проверяется по диапазону и сквозными ограничениями
  (мёртвая зона < ход, упоры сервы упорядочены и внутри 1000…2000, ход сервы
  ≠ 0). Пачка применяется атомарно: хотя бы одно значение вне границ — весь
  запрос отклонён (400), рабочий набор не меняется.
- **Сброс** (`POST /api/erase`): дефолты = константы `config.h`.
- **Калибровка** (`POST /api/calibrate`): запуск ручной калибровки хода (п.5.5)
  без удержания кнопки. Принимается только в READY, иначе игнорируется.
  Переход в CAL_MANUAL выполняется `loop()`, не HTTP-обработчиком.
- **Закрытие** (`POST /api/close`): гасит радио по кнопке в браузере.

### 11.3. Runtime-параметры и их хранение

Правке из веба подвержены: ходы и мёртвые зоны осей, rate limit набора/сброса,
пауза смены знака, экспонента руля, скорость хода сервы, программные упоры,
порог включения круиза, шаг и порог упора жеста, время возврата из круиза.
Инверсии осей, пины, тайминги арминга, тарировки и watchdog остаются константами.

Дефолт каждого — соответствующая константа `config.h`. Хранение — NVS тем же
способом, что и калибровка (magic + версия + FNV-1a CRC + обратное чтение),
отдельным ключом. Нет записи или запись невалидна — работа по `config.h`.
Так поведение до появления веба (v1.0) остаётся достижимым простым сбросом.

### 11.4. Требования к реализации

- Весь сетевой код исполняется в контексте `loop()`: один `handleClient()` за
  такт, без отдельных задач и блокирующих ожиданий. Такт 50 Гц и кормёжка WDT
  не должны зависеть от состояния сети.
- Команды браузера не изменяют состояние машины напрямую — только кладутся в
  очередь, которую `loop()` разбирает по одной за такт.
- Параметры применяются к копии, валидируются целиком и лишь затем коммитятся.
- Отказ радио, Wi-Fi или клиента не влияет наfail-safe: выходы и состояния
  живут по п.4/7 и без веба.

### 11.5. Стенд (дополнение к п.9)

13. Веб: AP гаснет через 60 с без подключения; не гаснет при подключении;
    закрывается при переходе в DRIVE и при FAULT; после закрытия не поднимается
    до перезапитки.
14. Параметры: значение вне диапазона отклонено целиком (рабочий набор не
    изменился); сохранённое значение переживает перезагрузку; `erase` возвращает
    константы `config.h`.
15. Калибровка из веба: работает только из READY, даёт тот же результат,
    что и вход удержанием кнопки.
16. Нагрузка: запросы статуса во время DRIVE не добавляют джиттера в такт
    (проверка по логу `esc`/`stb`), WDT не срабатывает.
